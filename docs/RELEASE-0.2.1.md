# MediaFlow 0.2.1 — audit hardening (staging release)

Baseline: uploaded MediaFlow 0.2.0. Public helpers and existing single-site URL/signature format are retained. No binaries or external PHP packages are bundled. Original images and existing derivatives are not bulk-deleted.

## Changes

- Explicit single-site support: block activation and skip runtime hooks on multisite; helper URL returns false there.
- Safe physical-size mode for new installs. Existing configured mode is retained. Preserve all registered cropped sizes and WordPress large-image downscaling; positional crops use native WordPress rendering.
- Verify HMAC before manifest lookup/recovery, including oversized-source requests. Never issue signed URLs with a missing/unpersisted key. Serialize new-key creation with a stable nonblocking lock.
- Settings write failures reach the admin instead of a success notice; runtime file is persisted before the DB backup option. Private temporary files are chmod 0600 before rename.
- Two concurrent encoders by default across derivatives and LQIP on one shared filesystem. Stable slot and variant locks; no unlink of generation lock inodes. Busy requests use existing no-store source fallback.
- Source limit 24 MP, output limit 8 MP, dimension limit 8192. Check actual source header and estimated PHP memory before decode. Default memory admission estimate is 16 bytes/source pixel plus 32 MiB and current PHP usage.
- LQIP creation only in upload capture or explicit CLI repair; visitors do not generate placeholders. Color changes apply immediately to newly rendered markup.
- Preserve crop-sensitive content HTML; skip already tagged MediaFlow images. Keep output dimensions aligned. Enforce final srcset candidate maximum while keeping display and highest selected width.
- Invalidate/rebuild on attachment file/metadata changes. Rebuild compares source URL as well as source identity. Add CLI repair and warming commands.
- Cleanup includes obsolete revisions inside active namespace, age retention, scan limit and resumable cursor. No automatic cleanup job.
- Correct Nginx private-directory example; expose signing status and processing limits in admin.

## Install / update

1. Back up the installed plugin directory, database, and MediaFlow private directory (especially secret.php and settings.json).
2. Install this ZIP on staging through Plugins → Add New → Upload Plugin; replace the existing MediaFlow plugin when prompted.
3. For Nginx, use the actual private URL path in the deny rule or set MEDIAFLOW_PRIVATE_DIR outside the document root. Do not change an existing private directory without copying its settings, signing key and manifests into the new location first.
4. Open Tools → MediaFlow. Confirm writable storage and signing status. Select Safe mode for initial validation.
5. Run the staging checks below. Purge HTML/page/CDN caches after settings or source changes where updated markup is needed. Do not rotate namespaces merely for this update.

## Commands

```sh
wp mediaflow status
wp mediaflow repair 123
wp mediaflow warm 123 --width=1200
wp mediaflow purge-stale --dry-run --limit=100 --scan-limit=1000 --retention-days=7
wp mediaflow purge-stale --limit=100 --scan-limit=1000 --retention-days=7 --yes
```

Use the printed `--after=00/00/123` cursor to resume. Empty cursor means restart (including when the removal limit stops inside an attachment). A final nonempty cursor can be followed until a run reports zero scanned roots. Root enumeration to reach a cursor is still filesystem traversal, not an indexed seek; scan-limit bounds inspected attachment work, not a strict wall-clock duration. Retention uses directory mtime, not last-access time. Run destructive maintenance during a quiet window with image generation paused; cleanup is not coordinated with other servers/workers. Old signed namespaces remain valid and can be regenerated by cached pages. Set retention longer than your HTML cache lifetime.

LQIP for existing attachments is rebuilt with `repair`; no automatic all-library sweep occurs. Feed selected critical image IDs into `warm` from your publishing workflow. There is no durable automatic background queue in this release: the shared admission limit bounds on-demand work.

## Server settings

Define before the plugin loads in wp-config.php if tuning is required:

```php
define('MEDIAFLOW_MAX_GENERATORS', 2);
define('MEDIAFLOW_MAX_SOURCE_PIXELS', 24000000);
define('MEDIAFLOW_MAX_OUTPUT_PIXELS', 8000000);
```

These are admission controls, not guaranteed memory ceilings. Configure ImageMagick memory/map/disk/time limits on the server and size PHP-FPM workers using measured encoder memory. Across multiple app hosts, lock/cache/private storage must be shared with working flock semantics; this build is intended for single-site, single-host staging first.

- All 14 PHP files parsed successfully with tree-sitter-php, including PHP 8 match expressions. This is not PHP lint/execution.
- Signature-before-recovery and admission-before-decoding source contracts checked.
- 24-process filesystem slot stress: peak two simultaneous holders, 22 immediate busy results, reusable stable slots. This tests OS lock semantics used by the design, not running PHP workers.
- ZIP integrity and baseline file/hash inventory generated.

PHP runtime was unavailable; installation attempt failed due environment permissions. Full PHP, WordPress, GD/Imagick, HTTP and visual tests were NOT executed. Historical benchmarks in SCALING.md belong to the supplied baseline and were not reproduced.

## Required staging checks

- Run `php -l` on every PHP file using PHP 8.1+.
- Activate on single-site; verify multisite activation refusal and no MediaFlow rewrite hooks.
- New JPEG/PNG/WebP uploads, transparent images, full-size, landscape/portrait, boolean crop and positional crop sizes; inspect editor and frontend cards/galleries at mobile/desktop widths.
- Hit one cold variant, then repeat: successful static hit must bypass PHP. Test invalid signature, unknown ID, oversized source, disabled encoder, full disk/unwritable private storage, concurrent same and distinct variants, HEAD request.
- Compare p50/p95 cold and warm TTFB, encoder RSS, PHP-FPM queue, DB queries, original fallback bytes, LCP/CLS and cache disk use against 0.2.0 on the same server.
- Change placeholder color, quality and format; verify srcset limit and crop composition. Toggle LQIP and repair one old image.
- Replace a source and update metadata; verify new revision. For out-of-band file copies run repair explicitly. Test private-directory migration with preserved key and updated source URLs.
- Run cleanup dry-run before removal; verify retention and old-revision selection on a copied test cache. Test rollback before production.

## Remaining boundaries

- No browser format negotiation/picture fallback. Auto prefers server-supported WebP; test your audience or use Original format.
- No object-storage/offload adapter, multisite support, distributed queue, automatic prewarming, negative failure cache or production telemetry.
- Whole-site page caches can retain old HTML after settings/revision changes. Purge those caches separately.
- Fingerprint still samples first/last bytes plus size/mtime/dimensions; an out-of-band replacement preserving these can evade revision detection. Use normal media replacement hooks and explicit repair; a future full-content hashing mode can address adversarial identical-metadata replacements.
- On memory/capacity failure the browser may receive the large original. Measure this bandwidth, especially on cold caches.

## Rollback

Restore the backed-up 0.2.0 plugin directory and settings snapshot, retaining the original signing key and source files. Existing derivative URLs keep their original signing format. Clear page caches. Avoid rolling back while a cleanup command is running. Lowercase and numeric URL format and both public helper names are unchanged.
